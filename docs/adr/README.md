# Architecture Decision Records

Architecture Decision Records capture decisions that are expensive to reverse or
affect multiple boundaries.

Use sequential names such as `0001-use-postgresql.md`. Each ADR includes:

- title, status, date, and owners;
- context and decision drivers;
- considered options;
- decision and rationale;
- security, privacy, tenancy, cost, and operational consequences;
- migration and rollback strategy;
- review date and superseding ADR, when applicable.

Statuses are `proposed`, `accepted`, `deprecated`, or `superseded`.
